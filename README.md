# Gyan Guardian Knowledge Networks

A responsive student learning portal with student registration/login, class-based learning resources, and an administrator-only resource manager.

## Features

- Student registration and sign-in with bcrypt password hashing.
- Administrator sign-in using deployment environment variables.
- Resource library with class filters (9, 10, 11, 12, Other and All).
- Admin-only create, edit and delete operations for learning resources.
- PDF and common video uploads.
- SQLite database and persistent upload storage.
- HTTP-only signed session cookie, security headers and authentication rate limiting.

## Run locally

1. Install Node.js 20 or newer.
2. Run `npm install`.
3. Copy `.env.example` to `.env`.
4. Set a private `ADMIN_PASSWORD` and a long random `JWT_SECRET` in `.env`.
5. Run `npm start`.
6. Open `http://localhost:3000`.

Never commit your real `.env` file or share the administrator password.

## Deploy on Render

1. Push this repository to GitHub.
2. In Render, choose **New → Blueprint** and connect this repository.
3. Render reads `render.yaml` and creates the web service and persistent disk.
4. Set the private `ADMIN_PASSWORD` environment variable in the Render service dashboard. Set a strong, unique password. `JWT_SECRET` is generated by the Blueprint.
5. Deploy and wait for the service to become live.
6. Open the Render service URL and test student registration, sign-in, admin sign-in and resource upload.

The persistent disk is mounted at `/var/data`, so the SQLite database and uploaded resources survive service restarts and deploys. The Blueprint uses Render's paid Starter web service and persistent disk; review current Render pricing before deployment.

## Administrator account

The administrator username defaults to `admin` and can be changed with `ADMIN_USERNAME`. The administrator password must be set as the private `ADMIN_PASSWORD` environment variable in Render. It is not stored in the source code.

## Notes

- This is an initial production-oriented starter. Before broad public use, add email verification, password reset, CSRF protection, upload malware scanning, backup/restore procedures and stronger audit logging.
- Student accounts currently use username/password only; no email or phone number is collected.
- Uploaded PDFs and videos are served to authenticated users through the resource URLs; consider private object storage and signed URLs if resources should not be publicly addressable.
